前提: 今回作ったもの

はじめてのタロットは、タロット全78枚の意味を学びながら、1枚引きからケルト十字まで段階的に占える日本語のiPhoneアプリです。

一言で表すと、次のようなアプリです。

カードの意味を調べる辞典と、カード同士のつながりまで読む占いを、静かに一つの端末で完結できるタロットアプリ。

最初の企画は大アルカナ22枚と1枚引き・4枚引きでした。その後、実機テストと内容レビューを繰り返し、現在は小アルカナを含む全78枚、複数スプレッド、履歴、内省メモ、買い切りProまで拡張しています。

技術スタックは、TypeScript / React Native / Expo SDK 54でアプリを実装し、EAS BuildでiOSアプリをビルド、TestFlightで実機配布する構成です。履歴や相談テーマはAsyncStorageでiPhone内に保存し、買い切りProだけをexpo-iap経由でAppleのStoreKitへ接続しています。鑑定は外部の生成AIやサーバーを呼び出さず、全78枚のデータとTypeScriptの合成ロジックだけで端末内生成します。

flowchart LR
  APP["React Native / Expo"] --> LOGIC["TypeScript鑑定ロジック"]
  APP --> LOCAL["AsyncStorage / 端末内履歴"]
  APP --> IAP["expo-iap / StoreKit"]
  APP --> EAS["EAS Build"]
  EAS --> TF["TestFlight"]
  TF --> STORE["App Store"]

この技術構成を選んだ理由

Swift / SwiftUIによるiOSネイティブ実装ではなくExpoを採用したのは、JavaScriptとTypeScriptの一つのコードベースで画面、占いロジック、Web確認まで進められ、AIとの反復開発がしやすいためです。初期公開はiPhoneに集中しますが、Android展開の余地も残せます。

一方で、すべてをWeb技術だけで済ませているわけではありません。App Storeの購入と復元はAppleの仕組みを使う必要があるため、そこだけはexpo-iapを通してネイティブ課金へ接続します。Expo Goでは画面を素早く確認し、実際の購入はネイティブコードを含むTestFlight版で確認する、という役割分担です。

また、バックエンド、会員データベース、外部AI APIを持たないことも意図した設計です。運用費を抑えられるだけでなく、相談内容を端末外へ送らないという、このアプリのプライバシー上の価値につながっています。

解決したい課題

既存のタロットアプリには、カードの意味が短すぎる、結果が抽象的で自分の状況へ結び付けにくい、逆位置が必要以上に否定的、複雑なスプレッドが正しい形で表示されない、といった使いづらさがあります。

このアプリでは、次の4点を中核価値にしています。

  1. 初心者は結論から読め、中級者は象徴やカード同士の関係まで掘り下げられる。
  2. 単語の羅列ではなく、質問、位置、正逆、カード全体の偏りを組み合わせて読む。
  3. 厳しいカードも「悪い未来の確定」ではなく、停滞・過剰・不足・内向化を整える手掛かりとして扱う。
  4. 相談内容や履歴を外部へ送らず、端末内で安心して使える。

対象ユーザー

  • タロットを初めて使い、カード名や基本の意味から学びたい人
  • 一通り意味を知っているが、複数枚のつながりを読むのが難しい人
  • 恋愛、仕事、お金、人間関係について、自分で考えるきっかけが欲しい人
  • 広告、ログイン、トラッキングのない静かな占いアプリを使いたい人

本アプリは未来や事実を断定するためのものではありません。占いを、自己理解、状況整理、次の行動を選ぶための補助線として扱います。

主な機能

無料で使える機能

  • タロット全78枚のカード辞典
  • 正位置・逆位置、象徴、物語、ブレインマップ、恋愛、仕事、金運、人間関係の解説
  • 端末ごとに一日固定される「今日の一枚」
  • 1枚引き
  • 過去・現在・未来・助言の4枚引き
  • Yes / No
  • あなた・相手・二人の関係を読む3枚の相性占い
  • 正式な十字と杖の配置で表示する10枚のケルト十字
  • 占い結果への気づきメモ
  • 結果の共有
  • 端末内履歴24件と、直近の逆位置傾向の振り返り

買い切りProで追加される機能

  • 7枚で二つの選択肢を比較する「選択の天秤」
  • 12枚で各月の流れを見る「一年の扉」
  • 端末内履歴の上限を24件から120件へ拡張
  • サブスクリプションではなく、一度購入すれば継続利用できる非消耗型課金

商品IDはhajimete_tarot_pro_lifetimeです。価格表示はアプリへ固定せず、StoreKitから利用者の地域に合う表示価格を取得します。

UXの5レイヤーで見る設計

Strategy: なぜ作るか

利用者のゴールは「未来を言い当ててもらうこと」だけではありません。カードを通して状況を整理し、自分が動かせる部分を見つけることです。

プロダクト側のゴールは、無料でも十分役立つ辞典と占いを提供し、もっと深く継続して使いたい人にだけ買い切りProを選んでもらうことです。

Scope: 何を提供するか

初期リリースでは、辞典、主要5スプレッド、履歴、メモ、共有を無料範囲としました。Proは無料機能を不自然に削るのではなく、枚数が多く設計も複雑な2スプレッドと履歴拡張を追加します。

会員登録、広告、解析SDK、通知、クラウド同期、実行時の生成AI通信は入れていません。機能を増やすより、鑑定文の一貫性、読みやすさ、プライバシーを優先しています。

Structure: どう流れるか

質問入力から結果までの基本構造は、すべての占いで共通です。

  1. 利用者がテーマを入力する。
  2. アプリが重複なしでカードを引き、各カードへ正位置または逆位置を割り当てる。
  3. スプレッド固有の位置へカードを配置する。
  4. 質問分野、位置、カード、正逆を組み合わせて各位置を読む。
  5. 複数枚の偏りと関係から全体像を合成する。
  6. 最後に、現実で試せる小さな行動へ落とし込む。
  7. 結果と任意のメモを端末内履歴へ保存する。

Skeleton: 画面上でどう配置するか

  • 最初に要約を置き、結論を探して長文をさまよわなくてよい構成にする。
  • 各位置には番号、役割、カード名、正逆を常に表示する。
  • 4枚引きは上段に助言、下段に過去・現在・未来を配置する。
  • ケルト十字は1〜6枚の十字と7〜10枚の杖を実際の展開形で表示する。
  • 長い鑑定は見出し単位に分け、具体的な読み筋と行動案を分離する。
  • 質問欄ではiPhoneのキーボード表示を考慮し、実行時にキーボードを閉じる。
  • 辞典は章ジャンプとブレインマップを備え、長文でも目的の項目へ移動できるようにする。

Surface: どう感じてもらうか

濃い茶、生成り、金色を基調とした紙面調の画面に、Rider-Waite-Smith系のカード画像を組み合わせています。神秘性は残しつつ、怖さや過剰な装飾よりも「落ち着いて読めること」を優先しています。

逆位置や厳しい結果では、意味を薄めて楽観的にするのではなく、現状の課題と変更可能な行動をセットで示します。利用者を落ち込ませず、同時に根拠のない安心も与えないトーンを目指しています。

鑑定生成のワークフロー

このアプリは、利用時にGPTや外部AIへ質問を送って鑑定しているわけではありません。78枚の独自データと、スプレッド別のルールを端末上で組み合わせて文章を生成します。

flowchart TD
  Q["利用者の質問"] --> C["恋愛・仕事・金運・人間関係などを推定"]
  C --> D["78枚から重複なしで抽選"]
  D --> O["正位置・逆位置を決定"]
  O --> P["スプレッドの位置へ割り当て"]
  P --> T["質問分野 × 位置 × 正逆で個別解釈"]
  T --> X["スート・大アルカナ・逆位置・数字の重なりを分析"]
  X --> S["要約・具体的な読み筋・全体傾向を合成"]
  S --> A["今日の一歩と内省の問い"]
  A --> H["端末内履歴へ保存"]

1. 質問を文脈へ変換する

入力された質問から、恋愛、仕事、金運、人間関係などの分野を端末内で推定します。相性占いでは、片思い、交際中、復縁、夫婦、仕事関係などの関係段階も読み分けます。ケルト十字では、質問に期間が含まれる場合、その時間軸も解釈へ反映します。

2. カード単体を位置の意味へ翻訳する

同じカードでも、現在、障害、潜在意識、近い未来、相手側、二人の関係、最終結果では読み方が変わります。カードの一般的な意味をそのまま貼り付けず、「その位置で何を表すのか」というレンズを通します。

3. 正位置と逆位置を読み分ける

逆位置は一律に悪い意味へ変換しません。カードごとに次の4軸のどれが強いかを持たせています。

  • 停滞: 力はあるが動いていない
  • 過剰: 力が強く出すぎている
  • 不足: 必要な力が十分に使えていない
  • 内向化: 外の出来事より内面で働いている

これにより、「悪いカードだった」で終わらず、何を調整できるかまで示します。

4. 複数枚の関係を読む

全体鑑定では、個々のカード以外に次のシグナルを確認します。

  • ワンド、カップ、ソード、ペンタクルの偏り
  • 大アルカナの枚数
  • 正位置と逆位置の比率
  • 同じ数字やコートカードの重なり
  • 相性占いにおける温度、緊張、安定、明瞭さ、相互性
  • ケルト十字における現在から結果までの連続性

この段階が、単なる「カード説明の横並び」と、スプレッドとしての鑑定を分ける部分です。

5. 行動へ落とし込む

最後は「当たる・外れる」だけで閉じず、連絡頻度を確認する、期限を決める、条件を書き出す、休息を取るなど、利用者が現実で試せる一歩へつなげます。

辞典コンテンツの構成

全78枚の辞典は、短い基本意味と長い学習プロフィールを分離しています。占い結果では短文を使い、辞典では次の章を深く読めます。

  • 大切な3ポイント
  • 世界観・人物像
  • 絵柄の象徴
  • 他カードとの物語的関係
  • リーディング上達のコツ
  • ブレインマップ
  • 正位置の意味・性質・助言
  • 逆位置の意味・性質・助言
  • 成長テーマと内省の問い
  • 恋愛、仕事、金運、人間関係それぞれの正位置・逆位置

参考資料や解説サイトは、論点、象徴、読みの幅を確認するために使います。著作権のある文章や図版をコピーせず、アプリ内の文章は独自に編集します。カード画像は、Wikimedia Commonsで公開されているRider-Waite-Smith系のパブリックドメイン画像を使用しています。

AIを使った開発ワークフロー

このプロジェクトでは、AIへ一度だけ「アプリを作って」と依頼したのではなく、iPhoneで実際に使い、違和感を見つけ、仕様へ戻して直す反復を続けています。

段階1: 企画を言葉で固める

対象ユーザー、カード範囲、必要な辞典項目、4枚引きの位置、無料版の範囲を会話で決めました。最初から全78枚や課金を入れず、核となる体験を明文化したことが土台になっています。

段階2: コンテンツと読み筋を設計する

カード単体の意味だけでなく、正逆、質問分野、位置、複数枚の関係をデータとルールへ落としました。Claudeによる大規模な内容改修も取り込み、その後にコードと画面の整合性をレビューしています。

段階3: 実装し、iPhoneで違和感を見つける

Expo GoとTestFlightを使い、画像、長文の切れ、キーボード、ケルト十字の配置、鑑定の具体性、否定的に感じる表現などを実機で確認しました。違和感を単なる感想で終わらせず、表示ロジック、文章生成、画面構造の修正へ戻しています。

段階4: 品質と権利を整える

型検査、Expo診断、iOS/Web書き出し、画像クレジット、プライバシーポリシー、個人データを含まないスクリーンショットを確認しました。外部サイトの文章や現代デッキ画像をそのまま使わない方針も、この段階で明確にしています。

段階5: 課金とApp Store公開へつなぐ

買い切りPro、購入復元、EAS本番ビルド、App Store Connect、TestFlight、サポートURL、審査用素材を整備しました。実装が終わってから公開方法を考えるのではなく、審査、権利、プライバシー、決済をプロダクトの一部として扱っています。

プライバシーと安全性の前提

  • 会員登録、氏名、メールアドレス、位置情報、連絡先を取得しない。
  • 相談テーマ、占い結果、内省メモは端末内だけに保存する。
  • 広告、アクセス解析、トラッキングを初期リリースへ入れない。
  • 実行時に質問をGPTや運営者のサーバーへ送信しない。
  • 利用者がOSの共有先を確定した場合だけ、選択した相手へ結果が渡る。
  • 履歴はアプリ内で削除でき、アプリを削除した場合も端末から消える。
  • 医療、法律、投資など重要な判断を占いだけで決めないよう明示する。

現在、アプリ本体と買い切りPro商品はAppleの審査待ちです。初期配信地域は日本に限定し、日本語版で利用体験と課金動作を確認してから、英語化と配信地域の拡大を検討します。

公開までに残る主な作業は次の通りです。

  1. Appleの審査結果を待ち、指摘があれば内容を確認して対応する。
  2. 承認後、日本のApp Storeで商品ページ、ダウンロード、Pro購入を確認する。
  3. 公開後の不具合、レビュー、Pro購入率を観察し、最初のアップデートへ反映する。

今後の改善候補

鑑定品質

  • 同じカードでも質問の期限や関係段階によって表現をさらに細分化する
  • カード同士の組み合わせパターンを増やす
  • 結論、根拠、注意点、具体策の重複を自動検査する
  • 肯定・否定の偏り、途中で切れた文章、抽象語の多さをテストデータで検出する

体験

  • お気に入りカード
  • テーマ別の質問テンプレート
  • 履歴の検索とタグ
  • 文字サイズや読み上げを含むアクセシビリティ改善

技術

  • 大きくなったApp.tsxを画面単位に分割する
  • 鑑定ロジックへ自動テストを追加する
  • 78枚すべての辞典項目と画像対応を機械検査する
  • 課金権利の確認方法を、将来のクロスデバイス利用に合わせて強化する

外部AIによる自由文鑑定を将来追加する場合は、明示的な同意、送信内容の確認、通信失敗時の扱い、利用料金、プライバシーポリシーとApp Privacy回答の更新が必要です。現在の「相談内容が端末外へ出ない」という価値を損なわないよう、既存の端末内鑑定とは分離して設計します。

まとめ

はじめてのタロットの開発で重要だったのは、AIに一度で完成品を作らせることではなく、次の順番を守ったことです。

  1. 誰のどんな困りごとを解決するかを言葉で決める。
  2. 必要な機能とコンテンツの範囲を決める。
  3. 辞典、質問、カード、スプレッド、結果の関係を構造化する。
  4. 実機で使い、文章と操作の違和感を仕様へ戻す。
  5. 権利、プライバシー、課金、審査まで含めて公開品質へ整える。

AIは企画、文章、実装、レビュー、公開準備を高速化できます。しかし、利用者が結果を読んだときに「自分の状況を整理できた」「次に何をすればよいか分かった」と感じるかどうかは、実際の利用体験を何度も見直すことでしか磨けません。この反復そのものが、アプリの新規性と品質を育てる中心ワークフローです。
